# Research: Verify Pi and npm package contract

## Summary
Context Hint must publish an npm tarball whose `package.json` has a `pi` manifest pointing at files present in that tarball. Put third-party runtime imports in `dependencies`; declare Pi host packages as `peerDependencies: "*"` and do not bundle them. Bundle any non-host Pi packages as both dependencies and `bundledDependencies` when their resources are referenced. Pi loads `.ts` through jiti, but built JS is the lower-risk npm entrypoint unless shipped TypeScript is self-contained without dev-only inputs.

## Findings

1. **[Blocker] Pi manifest paths must exist after packing.** Pi accepts `package.json.pi` arrays for `extensions`, `skills`, `prompts`, and `themes`; paths are relative to package root and support globs/exclusions. Without a manifest, Pi discovers convention directories: `extensions/`, `skills/`, `prompts/`, and `themes/`. The installed loader accepts `.ts` and `.js` extension entries and checks manifest paths exist before loading. When a valid `pi` object is present, it is authoritative: an omitted resource field does not fall back to that convention directory. Declare every resource category intended to load, and ensure every declared path survives npm packing. `keywords: ["pi-package"]` affects discoverability, not loading. [Pi docs — “Creating a Pi Package”, “Package Structure"](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/docs/packages.md); [source — `readPiManifest`, `collectPackageResources`, `resolveExtensionEntries`](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/pi-manifest.js) [/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/package-manager.js](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/package-manager.js) [/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/loader.js](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/loader.js)

2. **[High] Externalize Pi host packages; install other runtime dependencies.** Pi documents these host-provided imports as `peerDependencies` with range `"*"`, not bundled: `@earendil-works/pi-ai`, `@earendil-works/pi-agent-core`, `@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, and `typebox`. Other third-party runtime imports belong in `dependencies`. Other Pi packages must be in `dependencies` plus `bundledDependencies`, with resource paths under `node_modules/<package>/...`; Pi uses separate module roots. Current installed Pi 0.84.2 source installs npm packages with npm `--legacy-peer-deps` (Bun `--omit=peer`; pnpm peer auto-install disabled), and its extension loader aliases host Pi modules. Do not rely on npm installing those host peers into the package. [Pi docs — “Dependencies"](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/docs/packages.md); [source — `getNpmInstallArgs`, `loadExtensionModule`](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/package-manager.js) [/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/loader.js](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/loader.js); [npm docs — “peerDependencies”, “bundledDependencies"](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/)

3. **[High] TS loads, but built JS avoids registry-install/build ambiguity.** Pi’s extension docs say extensions load through jiti, so TypeScript works without compilation. The installed Node loader calls `jiti.import()` for the resolved entry and supports `.ts`/`.js`. Pi’s package docs also require distributed runtime dependencies in `dependencies`; dev dependencies are unavailable to the production runtime. A TS entry is safe only when all runtime imports, assets, and required path configuration ship and work without dev tooling. If build output is intended as runtime, point `pi.extensions` at built JS and include that output in the tarball. Do not assume a registry consumer will run a build after installation. [Pi docs — “Available Imports”, “Writing an Extension"](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/docs/extensions.md); [source — `loadExtensionModule`, `resolveExtensionEntries`](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/loader.js)

4. **[High] The packed tarball is runtime contract.** npm’s `files` field controls packed entries; without it, npm includes files by default subject to ignore rules and always includes `package.json`, README, LICENSE, and declared `main`/`bin` targets. Intended Context Hint tarball contents: `package.json`; manifest-targeted extension entry; every imported local module; runtime assets/resources; production dependency metadata; and any bundled dependency trees required by the Pi manifest. If `files` is present, explicitly include build output and resources. Pi’s own installed package uses an explicit `files` list containing `dist`, `docs`, `examples`, and metadata. [npm docs — “files"](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/); [npm docs — package preview](https://docs.npmjs.com/cli/v11/commands/npm-publish/); [first-party Pi package manifest](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/package.json)

5. **[Medium] Lifecycle scripts prepare packing, not a missing runtime artifact.** npm documents `prepack` and `prepare` around `npm pack`/`npm publish`; `prepare` also applies to git-installed packages. Use an existing build lifecycle only to make the package ready before packing, then inspect the resulting tarball. A clean registry-style install must work from packed contents with dev dependencies omitted. [npm docs — “Lifecycle Operation Order”, “prepare”, “prepack”, “npm pack”, “npm publish"](https://docs.npmjs.com/cli/v11/using-npm/scripts/)

6. **[Medium] Smoke checks.** In a disposable directory, run `npm pack --dry-run` and verify that `package.json`, the exact `pi.extensions` target, imported local files, resources, and bundled dependencies appear. Pack to a temporary destination; install that tarball with `npm install --omit=dev`; launch Pi against the installed entry with `pi -e <installed-package>/<manifest-entry>`. To exercise manifest/resource discovery, add the installed directory as a temporary local Pi package with `pi install -l <installed-package>` and start Pi in a trusted disposable project. Pass criteria: clean install, no missing-module errors, extension factory loads, and one harmless registration/event is observable. [Pi docs — “Install and Manage”, “Local Paths"](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/docs/packages.md); [Pi docs — “Quick Start"](/Users/chiminghang/.local/lib/node_modules/@earendil-works/pi-coding-agent/docs/extensions.md); [npm docs — `npm pack --dry-run`](https://docs.npmjs.com/cli/v11/commands/npm-publish/)
